# Claims register

Every number KudiGuard publishes, where it comes from, how to reproduce it and what it does **not** show. If a number
is not in this table, do not quote it. Last checked 10 Oct 2026 on this commit; an internal honesty audit (not an
independent one) re-ran the reproducible rows. Commands run from the repository root with the dev environment
(`pip install -e ".[dev,semantic,asr]"`); "live" rows need the N-ATLAS server (`scripts/run_llm.ps1`) and/or the local
model caches.

| P1 | N-ATLaS licence cap: ≤ 1,000 active end-users per rolling 30 days, all channels | `admission.py` (one gate owned by `Services`, used by WhatsApp, the website and the partner API) | `python -m pytest tests/unit/test_admission.py tests/unit/test_api.py tests/unit/test_pipeline.py -k "cap or burst or admission or twin or viral or failed or delete"` (mixed WhatsApp + web + API burst on SQLite, twin attack on web and API, viral timeouts) | **Guaranteed under these assumptions:** one server process (the gate is in memory; several instances would need a shared one); every served request holds a reservation until its interaction is written (counted per request, so a user's twin requests keep the slot until the last ends; a failed write keeps it for 30 days); only admitted turns are logged (a timed-out WhatsApp turn that never reached the gate leaves no row); the evidence log is never purged inside the window (retention ≥ 31 days).
